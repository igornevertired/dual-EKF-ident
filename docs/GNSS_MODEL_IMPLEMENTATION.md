# Где и как реализован ГНСС в проекте

Документ описывает **модель приёмника GNSS как источника наблюдений** в разомкнутой связке с БИНС: функция симулятора, параметры ошибок, как измерение входит в невязку и матрицу **R**.

---

## 1. Основная реализация

Единственная функция, формирующая «решение GNSS», находится в:

- [`src/model_python_port/core.py`](../src/model_python_port/core.py) — функция **`gnss`**.

Она экспортируется из пакета через [`__init__.py`](../src/model_python_port/__init__.py) и вызывается из [`bins_gnss_simulation.run_simulation`](../src/model_python_port/bins_gnss_simulation.py) **на каждом такте `dt_gnss`**.

Обёртки **«реального» решателя** (эллипсоидные преобразования, эфемериды спутников) **нет**: это упрощённая **генераторная модель наблюдений** «истина + белый шум» по шести скалярным каналам.

---

## 2. Каналы измерений и порядок вектора

Функция устроена как:

```text
[np_gnss, v_gnss] = gnss(fi_ист, lm_ист, h_ист, vn_ист, ve_ист, vh_ист, sigma_..., rng)
```

Выход **`np_gnss`** — один массив длины **6** строго в порядке:

| Индекс | Величина | Единицы |
|--------|----------|---------|
| 0 | Широта **φ** | рад |
| 1 | Долгота **λ** | рад |
| 2 | Высота **h** над эллипсоидом | м |
| 3 | Северная скорость **Vn** | м/с |
| 4 | Восточная скорость **Ve** | м/с |
| 5 | «Вертикальная» скорость для связки симулятора **Vh_nav** | м/с |

Те же три скорости в **`run_simulation`** подставляются из перехода **истинной** скорости ЛА через **`c_gb`**: порядок **Vn**, **Ve**, **Vh** согласован с выходом **`gnss`**.

На такте симулятора:

- К **истине** добавляются **независимые стандартные нормальные** ошибки приёма (**`rng.standard_normal()`** умножается на **σ** каждого канала).

После вызова приёмника невязка **z** упорядочивается как **ряды матрицы H** ошибочной модели (см. [SIMULATION_BINS_GNSS.md](SIMULATION_BINS_GNSS.md), раздел §3):

```text
z = [ δφ ; δλ ; δVn ; δVe ; δV_vert ; δh ]_INS−GNSS
```

соответственно столбцы **GNSS φ, λ**, затем скорости (без промежуточной высоты в середине), затем высота после скорости в невязке.

---

## 3. Значения СКО по умолчанию (`sigma_*`)

Параметры по умолчанию в коде **`gnss`** в `core.py`:

| Параметр | Смысл | Значение по умолчанию |
|---------|-------|-------------------------|
| `sigma_fi`, `sigma_lm` | ошибка угла | **5×10⁻⁶** рад |
| `sigma_h` | высота | **1.0** м |
| `sigma_vn`, `sigma_ve`, `sigma_vh` | скорости по осям | **0.2** м/с |

Вторая переменная выхода **`v_gnss`** — это просто столбец **σ** того же порядка, что **`np_gnss`**, переданный в матрицу шума измерений.

---

## 4. Формирование ковариации измерений **R**

В **`bins_gnss_simulation`** на каждом такте ГНСС:

1. По возвращённому **`v_gnss`** считаются **дисперсии** каналов `σᵢ²`.
2. Они упорядочиваются как **соответствуют строкам матрицы H** после перестановки каналов (см. комментарий в коде: сначала **φ, λ, Vn, Ve**, затем **V_vert**, затем **h**).
3. На диагональ накладывается **минимальный пол** (чтобы не получить сингулярную **S** при численно нулевой дисперсии у углов): значения задаются локально массивом «полов» совместимо с упорядоченными каналами.

Итого **R = diag(max(σ²_ordered_i, ε_i))`** — модель некоррелированного шумового приёмника.

---

## 5. Поток генератора случайных чисел

- В симуляторе создаётся **`np.random.default_rng(123)`** и пробрасывается в каждый вызов **`gnss(..., rng=rng_gnss)`**, чтобы наблюдаемость была воспроизводимая при том же коде и тех же параметрах.

---

## 6. Связь с ЕКФ (кратко)

**ГНСС** задаёт только **защумленный вектор уравнений наблюдений**, а **состояние ОФК** и **Jacobian / H по ошибке состояния** строятся в **`ofk_matrices`** — см. **`loosely_coupled_ofk.py`** и перенос **`BINS_OFK_2ch.m`** в **`bins_ofk_2ch.py`** (первые четыре строки **H** и расширения под вертикаль и высоту).
