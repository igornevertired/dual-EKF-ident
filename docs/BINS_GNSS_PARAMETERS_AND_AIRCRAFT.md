## 1. ГНСС: какие ошибки задаются и чем они равны

Функция: `core.gnss(fi, lm, h, vn, ve, vh, ...)`.

На каждое обновление (вызов раз в `dt_gnss`) к **истинным** географическим величинам и скоростям добавляются **независимые гауссовские шумы** с заданными СКО (`numpy.random`).

### Параметры по умолчанию (`sigma_*`)

| Величина | Смысл в коде | СКО (значение в коде) |
|----------|----------------|-------------------------|
| `sigma_fi` | широта φ | **5×10⁻⁶** рад |
| `sigma_lm` | долгота λ | **5×10⁻⁶** рад |
| `sigma_h` | высота h | **1.0** м |
| `sigma_vn` | северная скорость Vn | **0.2** м/с |
| `sigma_ve` | восточная скорость Ve | **0.2** м/с |
| `sigma_vh` | вертикальная скорость Vh | **0.2** м/с |

Истина → измерение: `измерение = истина + sigma * N(0,1)`.

В симуляторе дополнительно формируется диагональная матрица шума измерений ОФК: `R = diag(max(v_gnss², нижний_пол))`, где `v_gnss` — вектор из тех же шести СКО; полы нужны чтобы избежать вырождения численно очень маленьких дисперсий по углам (см. `bins_gnss_simulation.run_simulation`).

**Где вызывается:** на тактах `i % step_gnss == 0` с подстановкой истинных `x[12], x[13], x[10]` и компонент `v_nav` после перехода в навигационную СК через `c_gb`.

## 2. БИНС (ИНС): какие ошибки моделируются и чем они равны

Класс: `imu_error_generator.InsErrorGen`.

Это **приборная погрешность ДУС и ДЛУ** на входе алгоритма механизации (до шага БИНС).

### Байасы (один раз на объект генератора при создании)

- **ДУС (3 оси):** компонента `dw_bias[k] ~ N(0, 0.5°/ч)` в радианах на секунду (перевод: `0.5 * π / (180×3600)`).
- **ДЛУ (3 оси):** `da_bias[k] ~ N(0, 5×10⁻⁴)` м/с².

### Белый шум на каждый шаг генерации (`generate`)

- Угловая скорость: **СКО = `dw_noise_std` = `1×10⁻⁵`** (на один вызов, без явной привязки к √dt в этом классе).
- Ускорение: **СКО = `da_noise_std` = `5×10⁻⁵`** м/с².

Имеем:  
`ω_изм = ω_ист + dw_bias + N(0, dw_noise_std)`  
`a_изм = a_ист + da_bias + N(0, da_noise_std)`

**Seed в текущей связке симулятора:** конструктор `InsErrorGen(42)`.

### Механизация навигации

Один канал решения **`bins_common.bins_step`**: интегрирование скорости, координат и кватерниона ориентации с учётом вращения Земли, переносных и кориолисовых ускорений, гравитации из `earthmodel`; высота вертикальной скорости и высоты в навигации **жёстко подтягивается** из эталона полёта `h_et`, `dh_et` (иначе говоря, по вертикали часть связи берётся из «истины» модели траектории).

**Вектор навигационного решения БИНС в логах:** порядок  
`np_bins = [Vn, Vh, Ve, h, φ, λ]` — как в коде симулятора и ОФК.

## 3. Экспоненциальный фильтр Калмана (ОФК) в симуляторе

Модуль: `loosely_coupled_ofk.py`.

### Состояние фильтра (15 компонент)

Первые шесть: **`[dVn, dVh, dVe, dφ, dλ, dh]`** — ошибки скорости (в указанном порядке модели), широты/долготы и высоты. Остальные 9 связаны с углом платформы/дрейфами в упрощённой разомкнутой постановке (см. заполнение `F`, `G` в `ofk_matrices`).

### Измерение (невязка)

На такте ГНСС:

`z = [φ, λ, h, Vn, Ve, Vh]_INS − [···]_GNSS`  
(в коде сборка строки именно так: БИНС минус измерение датчика `np_gnss`).

Матрица связи **`H`** сопоставляет первые три строки ошибкам `dφ, dλ, dh`, три скоростные — ошибкам `dVn, dVe, dVh`.

### Экстраполяция и шум процесса

- `kf_predict`: дискретизация как в MATLAB `OFK.m`:  
  **Φ** = **I** + **F**Δt + (**F**Δt)²/2, **G_rus** = **G**Δt,  
  **P⁻** = **Φ** **P⁺** **Φ**ᵀ + **G_rus** **Q** **G_rus**ᵀ при Δt = **dt_gnss**.
- **`Q`** (диагональ в коде):  
  **`diag([1e-8, 1e-8, 1e-10, 1e-10, 1e-10, 1e-6])`**; вносится в предсказание ковариации через **G_rus Q G_rusᵀ** (размерность 15×15).

### Коррекция и обратная связь в БИНС

После `kf_update` решение БИНС уменьшается на поправку по индексам `np_bins` (соответствие положения ошибок в состоянии), затем **обнуляются первые шесть компонент состояния ОФК** `x_ofk[0:6]` (чтобы не считать одну поправку дважды между тактами в этой упрощённой схеме).

### Начальные ковариации `P`

В `run_simulation`:  
`np.diag([1e³]*4 + [1e⁻²]*6 + [1e⁻⁴]*5)` размерность 15.

### Первый такт ГНСС

Скорости БИНС инициируются по первому принятому пакету ГНСС (выравнивание скорости по наблюдению).

## 4. Как работает код симулятора (общий поток)

Файл: `bins_gnss_simulation.run_simulation(tmodel, dt, dt_gnss)`.

На каждый такт времени интеграции `dt` (по умолчанию **1 мс**):

1. **`rk4_step(fx1, ...)`** — продвигается **полная нелинейная модель ЛА** (`fx1`), управление **`u`** с предыдущего шага.
2. Из выходов RK берутся **истинное** ускорение и углосыскорость в связанной СК для «датчиков»: `af_bi_b`, `wbi_b`.
3. Каждые **0.01 с** (**100 Гц**) пересчитывается управление через **`autopilot(...)`** (удержание заданной высоты и скорости из `initsim`, удержание/изменение курса по кусочно‑заданному закону времени из `heading_hold`).
4. Приборная оболочка: **`InsErrorGen.generate`** искажает `w`, `a`.
5. **`bins_step`** обновляет `np_bins`, кватернион и **`Cbn`**.
6. Каждые **`dt_gnss`** (обычно **0.1 с**): генерация наблюдений **`gnss`**, расчёт `z`, сборка `F,G,H,Q,R`, **`kf_predict` + `kf_update`**, поправка `np_bins`, лог строки результатов по тактам ГНСС.

Выход — словарь массивов с длиной **число эпох ГНСС** (ключи времени `time`, истина/BINS до коррекции/после ОФК при необходимости, ошибки и т.д.).

## 5. Модель летательного аппарата: что это за объект и как описана динамика

### 5.1. Назначение и происхождение

**`fx1.FX1`** — порт нелинейной **шестистепенной** модели с аэродинамикой, тягой и гравитацией (эллипсоид через `earthmodel`), переносными и кориолисовскими членами для скорости, кинематикой по углам и координатам (широта/долгота/высота в состоянии), **динамикой приводов** органов управления (передаточные звенья задаются временами **`T_THROTTLE`, `T_ELEV`, `T_RUD`, `T_AIL`** из `initla`), а также упрощёнными элементами режима набега высоты/посадки при малых высотах (см. комментарий в заголовке `fx1.py`).

### 5.2. Массо-геометрические параметры из `initla`

- Масса (первый элемент `PAR[0]`): **`1.7×10⁵` кг** — тяжёлый ЛА транспортного класса по порядку величины.
- **`PMAX` = `2.6×10⁵`** Н — типовая номинальная тяга (используется с относительной дроссельной заслонкой **`δT`**).
- Константы времени приводов: дроссель **5 с**, руль высоты **0.1 с**, руль направления и элероны **≈ 0.0495 с** (`1/20.2`).
- Полный массив **`PAR`** (около пятидесяти скалярных производных коэффициентов сил и моментов, размах, площадь и т.д.) задан статическим вектором в `initla.py` — именно они определяют **конкретные численные силовые коэффициенты CX, CY, CZ, MX, MY, MZ** как функции состояния и отклонений рулей.

### 5.3. Вектор состояния `x` (25 компонент)

Сборка из `intstate.intstate`; типовой порядок (совпадает с комментарием в `FX1`):

| Индексы | Содержание |
|---------|-------------|
| 0–2 | проекции **воздушной скорости** на оси связанной СК (Vx, Vy, Vz при постановке из углов атаки/скольжения) |
| 3–5 | угловые скорости в связанной СК Wx, Wy, Wz |
| 6–8 | углы: крен, курс ψ, тангаж θ связанной СК (см. использование индексов в `FX1`, `c_gb`) |
| 9–11 | горизонтальные координаты траектории L, высота **H**, Z |
| 12–14 | географическая широта, долгота, доп. параметр траектории `d` |
| 15–18 | состояние **приводов** (ответ на команды управления органами) для δT, δV, δN, δE |
| 19–21 | составляющие ветра |
| 22–24 | вспомогательные переменные посадочного контура (HFL, EPS, X1) |

Подробнее — строка за строкой см. сборку массива в `intstate.py`.

### 5.4. Управление `u` и номинальный полёт

- Управление: **`u = [δT, δV, δN, δE]`** — относительная тяга и отклонения рулей высоты, направления, элеронов с насыщением (`autopilot_model.autopilot`, пределы `UMAX`, `UMIN`).
- При инициализации **`initsim.initsim`**: находится балансировка **`BAL = [δT, α, δV, δN, δE]`** методом координатного спуска минимизации силового дисбаланса (порт процедуры **`BALANCING` / `FCT`**), задаётся **номинально:** высота траектории **`htr = 500 м`**, скорость **`vtr = 80 м/с`**, траекторные угол и крен в горизонтальном режиме **0**.
- После этого автопилот **удерживает** эти цели плюс вводит запрограммированные **кусочно‑линейные манёвры изменения программного курса** во временные интервалы **100–300 с**, **400–550 с**, **700–900 с** (градусы задаются через комбинации с параметром конфигурации `Wy`; при коротких прогонах эти интервалы могут просто не наступить).

Итого: «мой ЛА» в коде — **конкретный эталон с фиксированным набором аэродинамических производных из `PAR`**, большой массы, с **наземными целями 500 м / 80 м/с**, полётом через **RK4** с управлением **автопилотом MATLAB‑портов**.
