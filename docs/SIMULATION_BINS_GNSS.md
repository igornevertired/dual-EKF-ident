# Описание сценария симуляции БИНС / ГНСС / ОФК

Этот документ описывает, что **моделируется с каких приборов и с какими ошибками**, как работает **оптимальный фильтр Калмана (ОФК)** в разомкнутой схеме с ГНСС, и что **получаем на выходе**. Реализующий код: пакет `src/model_python_port`, точка входа `run_full_sim.py`.

**Табличный вынос всех численных СКО, поток временного цикла и модель ЛА (динамика `FX1`, состояние, автопилот):** [BINS_GNSS_PARAMETERS_AND_AIRCRAFT.md](BINS_GNSS_PARAMETERS_AND_AIRCRAFT.md).

**Только про реализацию БИНС (файлы, `bins_step`, ошибки ИНС):** [BINS_NAVIGATION_IMPLEMENTATION.md](BINS_NAVIGATION_IMPLEMENTATION.md).  
**Только про модель ГНСС в коде (`core.gnss`, σ, порядок z и R):** [GNSS_MODEL_IMPLEMENTATION.md](GNSS_MODEL_IMPLEMENTATION.md).

## 2. Приборная часть: что моделируется и ошибки

### 2.1. ДУС и ДЛУ (канал инерции до механизации)

Класс `InsErrorGen` формирует **измеренные** угловые скорости и ускорения в связанной СК для шага БИНС:

- **Смещение (байас) гироскопа** по трём осям: случайное `Normal(0, 0.5°/ч)` (перевод в рад/с).
- **Смещение акселерометра** по трём осям: `Normal(0, 5·10⁻⁴)` м/с².
- **Белый шум** добавки к каждому шагу: СКО угловой скорости `10⁻⁵` (единиц модели входа ω), СКО ускорения `5·10⁻⁵` м/с².

Истинные ω и фиктивная аэромужная сила (переводящаяся в ускорение для БИНС) задаются решением ОДУ `fx1` через `rk4_step`; к ним прибавляются ошибки генератора и полученный поток поступает в `bins_step`.

### 2.2. ГНСС (после решения по спутникам — упрощённая модель)

Функция `core.gnss` не моделирует эфирис и псевдодальность: она добавляет к **истинным** координатам и компонентам скорости (из модели полёта) **независимые гауссовы шумы** с параметрами по умолчанию:

| Приборный вывод | Обозначение | СКО по умолчанию |
|-----------------|-------------|-------------------|
| Широта | σ_φ | 5·10⁻⁶ рад |
| Долгота | σ_λ | 5·10⁻⁶ рад |
| Высота | σ_h | 1 м |
| Северная скорость | σ_Vn | 0.2 м/с |
| Восточная скорость | σ_Ve | 0.2 м/с |
| Вертикальная скорость | σ_Vh | 0.2 м/s |

При коррекции в фильтре ковариация измерения **R** строится из этих же дисперсий (`v_gnss²`) с небольшими нижними границами для численной устойчивости (`bins_gnss_simulation.py`).

### 2.3. Особенность высоты в БИНС

В шаге `bins_step` **высота и её производная** подставляются из истинной траектории ЛА каждый микрошаг. Поэтому «чистое» расхождение БИНС и истины по высоте в отчёте до ОФК близко к нулю, а наблюдаемый разброс по каналу h в большей части отражает только **выход ГНСС** относительно модели высоты.

## 3. Как работает ОФК (разомкнутая схема)

1. На каждом физическом шаге `dt` считаются динамика ЛА, автопилот и **механизация БИНС** с зашумлёнными ΔУС/ДЛУ. Навигационный вектор `np_bins = [Vn, Vh, Ve, h, φ, λ]` обновляется непрерывно.

2. С периодом **dt_GNSS** (по умолчанию **0.1 с**) считываются «решения приёмника» `gnss` и образуется **вектор невязки** **z**, согласованный со строками **H**:  
   \[δφ, δλ, δVn, δVe, δVh, δh\] = БИНС − ГНСС (первая четверка соответствует переносу `BINS_OFK_2ch.m`, два последних канала — расширение под вертикальную скорость и высоту).

3. **F**, **G** (первые 13 строк/столбцов состояния) строятся переносом **`BINS_OFK_2ch.m`** (:mod:`bins_ofk_2ch`); добавлены два состояния **14–15-го порядка** (индексы 13 и 14) с затуханием для ошибок сохранённой вертикальной скорости в `np_bins` и высоты. Процессный шум **Q** задаётся как в MATLAB (**diag((Wq²)/dt_nav)** из того же файла).

4. На такте ГНСС выполняются:
   - **Предсказание** (как в MATLAB `OFK.m`): \( \Phi = I + F \Delta t + (F \Delta t)^2 / 2 \), \( G_{rus} = G \Delta t \),  
     \( \hat{x}^- = \Phi \hat{x}^+ \), \( P^- = \Phi P^+ \Phi^{\mathsf{T}} + G_{rus} Q G_{rus}^{\mathsf{T}} \) при `Δt = dt_gnss`.
   - **Обновление (ЕКФ)**: коэффициент усиления через `solve(S, ·)`, симметричная **Joseph** форма для **P⁺**.

5. **Обратная связь в решётку БИНС**: вычитаются соответствия из оценённого ошибочного вектора (индексы состояния **3–6** MATLAB-порядка для Vn, Ve, φ, λ и индексы **13–14** для вертикальной скорости/высоты). После этого **весь вектор оценки ошибки обнуляется** («reset» error-state между тактами).

## 4. Выход симуляции

### 4.1. Словарь `run_simulation(...)`

На выход возвращается словарь **массивов длины числа тактов ГНСС**. Основные поля:

- **«Истина»** (генератор опорной траектории ЛА в навигационных осях): `true_*` — высота, φ, λ, Vn, Ve, Vh; `time` — секунды.
- **«БИНС до очередной коррекции ОФК»** на этом такте: `bins_*` (до вычитания оценённой ошибки).
- **«ОФК / скорректированный решётчик»**: `ofk_*` — то же шестиканальное наблюдаемое после поправки.
- **ГНСС**: `gnss_*` для тех же каналов.
- **Ошибки** относительно истины: `err_bins_*`, `err_ofk_*`.
- **СКО апостериори** по ошибке состояния (корень из диагонали **P**) для ключевых навигационных компонент: `ofk_std_fi`, `ofk_std_lam`, `ofk_std_h`, `ofk_std_vn`, `ofk_std_ve`, `ofk_std_vh`.
- **Управление** на такте ГНСС: `u` размерность 4 × N.

Отдельную программу анализа можно строить, импортируя `run_simulation` из `model_python_port.bins_gnss_simulation` или сценария `run_full_sim.py`.

### 4.2. Файлы при `python run_full_sim.py`

- **`bins_gnss_full.png`** — сетка 2×3: истина, БИНС до ОФК, ОФК, точки ГНСС по шести каналам (`plot_bins_gnss_trajectory_dashboard`).
- **`control_surface_deflections.png`** — четыре канала вектора управления **`u`** по тактам ГНСС (`plot_control_vector_deflections`). В словаре результата при необходимости анализа сохраняется также **`u0`** (номинал из `initsim`).
- **`plots_sigma/ofk_error_vs_three_sigma_P.png`** — ошибка после ОФК относительно истины и зона ±3 σ по апостериорной диагонали **P** (`plot_ofk_error_with_posterior_three_sigma`).

### 4.3. Консоль

Краткая выборка табличного лога: `print_bins_gnss_simulation_tables`.
